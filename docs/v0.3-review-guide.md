# v0.3 protocol reviewer guide

## Review state

v0.3 is a **protocol draft**. There is no v0.3 evaluator, comparator, sealed
case pack, live run, or result claim. The immutable review commit is recorded in
the review PR rather than inside this file, because a commit cannot contain its own SHA.
A semantic change creates a new review target.

This v0.3.10 successor preserves every earlier object-bound review record; it
does not reinterpret or revoke one. The latest predecessor review returned
`REQUEST_CHANGES` for exact v0.3.9 commit
`396aa38027e7a605c0864231d9602d0055f5262f`. Its
[`v0.3.9 disposition`](reviews/v0.3.9-review-disposition-2026-08-24.json)
accepts `ACP-V03-014` and `ACP-V03-015` for remediation and holds case sealing
pending a fresh review of an exact successor SHA.

The v0.3.10 remediation closes classification and provenance roles into one
relation: claim-chain records and non-target authorization-path prefixes must
be `VALID`, `NONMATCHING` records cannot be decisive, decisive `UNRESOLVED`
records correspond exactly to `INDETERMINATE` authority for conformant runs,
and `INVALID` authority requires decisive invalid evidence. Complete-pack mode
also requires an exact trusted `expected_approved_protocol_commit` obtained
outside the pack from the object-bound owner/review decision. The public
commitment and population freeze must both match it; self-consistency alone no
longer establishes the approval object. The decision also supplies the digest
of a closed approved-protocol manifest, and complete-pack validation recomputes
every governing protocol, schema, guide, and validator byte against it.

The historical records remain available in the review table below. Green
checks on this successor are bounded evidence only; they do not open case
sealing or implementation.

The approved v0.2.2 implementation and compact result remain in the repository
as historical context. They are not evidence that v0.3 is valid.

## Synthetic fixture warning

Everything under `tests/fixtures` is synthetic and non-production. The authority
vectors intentionally disclose deterministic private-key seeds so independent
reviewers can reproduce keys and signatures byte for byte. Those seeds are
public test material and must never authenticate real authority or be copied
into a production trust store.

## Review boundary

In scope:

- deterministic signature, time, scope, lineage, recovery, revocation,
  rollback, precedence, conflict, and provenance semantics;
- whether independent implementations can produce identical results;
- whether independent oracle authors can apply the closed output rules
  consistently; and
- authorship, leakage, sealing, population, comparator, and stage-gate rules.

Out of scope:

- legitimacy of any real-world issuer, organization, or root;
- production key custody, deployment security, or compromise response;
- v0.3 evaluator or comparator quality, because neither exists yet;
- final blind cases, prompts, live API runs, performance, or result claims; and
- reopening the already approved v0.2.2 result.

`APPROVE_FOR_CASE_SEALING` means the reviewer, while bound to one immutable SHA,
can reconstruct the protocol without private author interpretation, reproduce
the fixtures independently, and finds no unresolved ambiguity likely to make
independent implementations or oracle labels diverge. It opens only the
case-sealing stage. It does not approve implementation, experimental validity,
production security, or a real-world authority claim.

`REQUEST_CHANGES` means any unresolved ambiguity, contradiction, missing
ordering rule, non-reproducible fixture, or case-sealing defect could produce
divergent implementations, labels, provenance, or scoring. Disagreement is a
protocol defect, not something to adjudicate with unrecorded author intent.

No final blind case may be authored or exposed before protocol approval.

## Validation

Python 3.11 or newer is required. From a clean checkout:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install ".[dev]"
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
.venv/bin/python scripts/generate_authority_vectors.py --check
.venv/bin/python scripts/validate_v03_artifact.py --help
.venv/bin/python -m contextproof.cli --json --require-ready
```

The CLI command reproduces the approved offline v0.2 mechanism. The pytest,
Ruff, and vector commands validate this v0.3 protocol draft. No API key is
required for any command above.

## Workflow behavior

- `.github/workflows/ci.yml` runs automatically for pull requests and pushes to
  `main`. It installs dependencies, runs the offline tests and Ruff, and invokes
  the deterministic v0.2 CLI. It makes no model API request.
- `.github/workflows/live-eval.yml` runs only when a maintainer invokes
  `workflow_dispatch`. It requires the `OPENAI_API_KEY` repository secret, runs
  the v0.2 live comparison, and retains its uploaded result artifact for 14
  days. It is not a v0.3 review check or proof gate.
